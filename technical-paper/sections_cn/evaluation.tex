\section{任务完成超过评分覆盖}
\label{sec:evaluation}

\textbf{实验协议。} 三个云端端点在同一个代码修订版和
\CampaignCreditLimit{} 积分限制下处理相同的 \CorpusTaskCount{} 个均衡任务。
每个完成的输出必须通过 \CSim、\Synth、100 MHz、U55C 容量以及 Track-A
契约~\cite{fpt26tracka} 下所有适用的 \CoSim{} 门。对于原始记录中存在 API
调用失败的任务，合并后的语料选择可用的定向重跑记录并重新计算完成数。"已评分"
指标统计评估分数非空的任务；重跑并未为每个恢复完成添加评分。合并后的记录中
仍存在 \DeepSeekApiFailures{}、\QwenThreeFiveApiFailures{} 和
\QwenThreeSixApiFailures{} 次失败请求。
附录~\ref{app:benchmark} 说明任务来源；附录~\ref{app:results} 给出类别和
选中记录的核算详情。

\textbf{结果。} DeepSeek 提供了最广泛和最均衡的覆盖：
\DeepSeekSuccessCount{}/\CorpusTaskCount{} 个完成，各类别均至少达到 24/25。
Qwen3.5 少完成一个任务，但其 \QwenThreeFiveScoredTaskCount{} 个可评分任务
构成最大的评分集合，并产生最高总分 \QwenThreeFiveScoreSum。DeepSeek 的
更高评分均值 \DeepSeekScoredMean 适用于不同的
\DeepSeekScoredTaskCount{} 个任务子集，因此并不构成成对质量优势。

Qwen3.6 达到 \QwenThreeSixSuccessCount{} 个完成，包括编译修复、综合修复和
QoR 优化三个类别的满分 25/25。其残余差距集中在结构修复（18/25）和代码生成
（21/25）。仅 \QwenThreeSixScoredTaskCount{} 个 Qwen3.6 任务具有评估分数，
因此其总分并不能衡量大多数恢复后的完成。评分覆盖不均和残余的 API 失败
阻碍了将端点差异完全归因于模型权重。
