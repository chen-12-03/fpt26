\section{Benchmark Composition}
\label{app:benchmark}

The manifest freezes every upstream path, commit, task description, test,
and gate configuration, retaining \CorpusTaskCount{} tasks with no
cross-category kernel overlap. Table~\ref{tab:task-composition} describes
the six balanced capabilities, each containing \TasksPerCategory{} tasks.
Only the structural category requires C/RTL co-simulation.

\begin{table}[H]
  \caption{\textbf{Task suite composition.}}
  \label{tab:task-composition}
  \centering
  \small
  \begin{tabular}{lrr}
    \toprule
    Task type & Tasks & \CoSim{} \\
    \midrule
    Code generation (stub $\to$ kernel) & 25 & 0 \\
    Compile repair & 25 & 0 \\
    Synthesis repair & 25 & 0 \\
    Functional repair (\CSim{}) & 25 & 0 \\
    Structural repair (\CoSim{}) & 25 & 25 \\
    QoR optimization & 25 & 0 \\
    \bottomrule

Kernels come from two public AMD repositories at fixed commits:
\url{https://github.com/Xilinx/Vitis-HLS-Introductory-Examples}
(\IntroExampleTaskCount{} tasks, Apache-2.0, \texttt{aa5c160f}) and
\url{https://github.com/Xilinx/Vitis_Accel_Examples}
(\AccelExampleTaskCount{} tasks, MIT, \texttt{81187602}).
The 150 variants reuse \UniqueSourcePathCount{} unique source paths.

\section{Independent Evaluator Results}
\label{app:evaluator-results}

The evaluator reruns each of the \IndependentEvaluatedCount{} final kernels
that passed the public gate. All \IndependentHiddenCorrectCount{} pass
evaluator-side hidden correctness, which requires hidden \CSim, candidate
synthesis, and required hidden \CoSim.
Table~\ref{tab:evaluator-results} separates this correctness result from
reference-score coverage.

Full-corpus reference means remain unavailable because some frozen
starter/reference syntheses report data-dependent or missing latency and
interval metrics. On the \CommonReferenceTaskCount{} tasks with valid scores
for every endpoint, the means are DeepSeek \DeepSeekCommonReferenceMean{},
Qwen3.5 \QwenThreeFiveCommonReferenceMean{}, and Qwen3.6
\QwenThreeSixCommonReferenceMean{}. One Qwen3.5 report stops with
\texttt{required\_metric\_missing} after evaluator-side hidden correctness
passes because neither anchor supplies the required fixed metric.

\section{Reproduction}
\label{app:reproduction}

Task list: \path{tasks/track_a_150/candidate_manifest.json}.
Campaigns: \path{runs/150_ultimate/}. We audited the proxy macros in
\path{technical-paper/results_generated.tex} from the selected optimization-task
\path{run_report.json} files using the definition in
Section~\ref{sec:evaluation}. Independent evaluator macros in
\path{technical-paper/evaluator_results_generated.tex} come from
\path{technical-paper/evidence/track_a_150_reevaluation_summary.json} via
\path{technical-paper/scripts/update_evaluator_results.py}. The existing
\path{update_results.py} helper targets a separate \path{final_report.json}
schema and does not generate either table.

All campaigns: source snapshot {\small\ExecutionSourceHash},
temperature~0, 4,096-token output limit, 180\,s request timeout, $\leq$2
retries.
