# 预算约束下大语言模型辅助高层次综合的验证候选循环

**匿名投稿**

---

## 摘要

高层次综合（HLS）智能体必须在有限的大语言模型（LLM）和工具预算内修复和优化不熟悉的内核。我们提出了验证候选循环（Verified-Candidate Loop, VCL），它让经过测量的验证证据来控制候选方案的晋升。一个有界的质量结果（QoR）评分将有效延迟和最坏资源增长结合起来。QoR 引导的检索增强生成（QoR-RAG）复用兼容的测量证据，而失败反思（Failure Reflection）则将工具诊断信息转化为下一步的约束条件。在一个由两个固定 commit 的 AMD 仓库构建的、均衡的 150 任务套件上，三次托管模型实验解决了 88.0% 到 98.0% 的任务。所有模型都解决了全部 25 个 QoR 优化任务。结构性 C/RTL（寄存器传输级）协同仿真修复是最大的跨模型差距来源。

**关键词：** 高层次综合，LLM 智能体，FPGA，检索增强生成，结果质量

---

## 1. 证据必须控制 LLM 编辑

HLS 工程师必须理解不熟悉的 C/C++ 内核，修复功能和流式传输故障，并在较小的评估预算下调优硬件。仿真和综合报告揭示了正确性和性能证据。LLM 可以提出源代码更改，但其文本无法证明接口、RTL 执行或硬件权衡的正确性。

LLM 辅助的 HLS 系统自动化了代码转换和设计空间探索。ChatHLS 进一步将生成、指令调优和反馈驱动的调试智能体分离开来。通用的工具使用智能体将模型推理和操作交替进行。一个有计量的 HLS 循环还需要一个候选方案晋升规则。一个未经检查的编辑可能通过编译，却在隐藏测试中失败、在 RTL 中死锁、无法达到 100 MHz，或者消耗的硬件资源超过了其加速所值得的。

我们的验证候选循环（VCL）贡献了三种机制：

**(1)** 一个故障关闭（fail-closed）的接口和验证工作流，保留一个经过验证的回退方案。

**(2)** 一个有界硬件评分 Q_HW，拒绝虚假的加速。

**(3)** QoR 引导的检索增强生成（QoR-RAG）和失败反思，将后续尝试聚焦于兼容的证据。

我们在总共 T 次托管模型任务运行中评估了完整的智能体。

## 2. 工具证据控制智能体工作流

任务接口提供一个可编辑的内核、其顶层函数签名、公开测试、目标器件和预算。通过一个统一的工具接口，智能体提交完整的源文件、请求验证并读取结构化报告；它永远不会收到隐藏测试或冻结的参考实现。预检（Preflight）在 LLM 或 HLS 工具消耗预算之前拒绝格式错误的输入。控制器在运行状态中记录每个候选方案、门控、指标、token 和信用额度。

VCL 运行接口检查、C 仿真（CSim）、HLS 综合（Synth）、100 MHz 频率检查、U55C 容量检查、任务所需的 C/RTL 协同仿真（CoSim），以及指标完整性检查。设每个适用的门控 G_i ∈ {0, 1}。我们将不适用的 CoSim 门控设为一：

```
V(c) = G_int · G_csim · G_syn · G_freq · G_cap · G_cosim · G_metric
```

设 b 表示经过验证的回退方案。晋升规则为：

```
P(c) = V(c) ∧ [Q_HW(c) > Q_HW(b)]
```

预算准入为所有必需的门控预留信用额度。门控失败或预算拒绝则保留 b。QoR-RAG 提供版本兼容的规则、成功案例和测量到的失败。失败反思将有界诊断信息和候选方案差异转化为下一个约束条件，而无需额外的 LLM 请求。重复的指纹和重复的失败签名会停止无效的重试。隐藏验收仍然是评估方一侧的检查。

> **图 1：测量证据控制每一次状态转换。** 智能体通过一个有界接口提出建议；只有通过每个适用门控并改进 Q_HW 的候选方案才能替换经过验证的回退方案。

## 3. 一个评分拒绝虚假加速

评估器选择一个有效的起始方案作为锚点 a，并回退到智能体无法检查的冻结参考实现。设 c 表示一个候选方案，L 为其周期延迟，p = max(p_target, p_estimated) 为其有效周期，II 为其启动间隔。评分仅在任务标记 II 相关且两个值均为正时才使用 II 分支：

```
r_L = (p_a · L_a) / (p_c · L_c)

r_P = { r_L^0.85 · (II_a / II_c)^0.15,  可靠的 II
      { r_L,                              仅延迟
```

对于锚点和候选方案的资源计数 A_j 和 C_j，设 R 包含查找表（LUT）、触发器（FF）、数字信号处理（DSP）块、块 RAM（BRAM）和 UltraRAM（URAM）。最坏资源增长定义了面积质量：

```
R_+ = {j ∈ R : A_j > 1 ∨ C_j > 1}

Ř = { R_+,  若 R_+ ≠ ∅
    { R,    若 R_+ = ∅

r_A = [max_{j ∈ Ř} (max(C_j, 1) / max(A_j, 1))]^(-1)
```

官方评分结合了有效性、有界硬件效用和预算效率：

```
h = r_P^0.55 · r_A^0.45

Q_HW = 1 - 1 / (1 + h)²

E = max(0.80, 1 - 0.10 · u_credit - 0.10 · u_time)

S = 100 · V · Q_HW · E
```

其中两个 u 项表示消耗的信用额度和时间比例，截断到 [0, 1]。晋升仅在 V(c) = 1 之后比较 Q_HW，因此剩余预算不会使较差的设计成为回退方案。

## 4. 三个模型揭示了困难案例

### 任务与来源

冻结的任务套件包含 N 个任务，在生成、编译修复、综合修复、功能修复、结构性 CoSim 修复和 QoR 优化六个类别中各均衡分配了 K 个任务。其中 M1 个内核来自 AMD 的 Vitis HLS 入门示例，M2 个来自其加速示例（均为固定 commit）。构建器添加受控故障、公开测试、仅评估器使用的隐藏测试和冻结参考实现。附录 A 记录了完整的组成和溯源。

### 实验方案

三次实验通过应用程序接口（API）调用托管模型。它们使用相同的 150 个任务、C 个信用额度、相同的智能体源代码版本、Alveo U55C 目标器件和 Vitis 2025.2。清单定义的门控合约应用了 Track-A 的运行时要求。仅当输出通过 CSim、Synth、100 MHz、容量和每个任务适用的 CoSim 门控时，我们才计为成功。R 个结构性任务要求 CoSim。缺失或失败的必需证据计为失败。报告记录模型身份、隐藏测试结果、token、工具调用、信用额度、频率和硬件指标。这是对适用运行时合约的严格遵循；PDF、源代码归档和视频仍然是单独的提交包检查项。

### 结果

DeepSeek V4 Pro 以 X/N 的成功率领跑，具有最高的 QoR 评分（S1）和最低的 token 总量（T1 百万）。Qwen3.5 解决了 Y 个任务，但使用了 T2 百万 token。Qwen3.6 在结构性 CoSim 修复上仅达到 R3%，而其他两个模型分别为 R1% 和 R2%。结构性修复占其与 Qwen3.5 之间 Z 个成功差距中的 W 个。所有模型都解决了全部 25 个 QoR 任务，但它们的平均 QoR 评分各不相同；因此，完成率本身不能衡量优化质量。详细的类别、预算和 token 结果见附录 C。

> **要点：** 模型选择对结构性修复可靠性和 token 成本的影响，比对二元的 QoR 任务完成率的影响更大。

## 5. 局限性与后续工作

VCL 将验证证据和 Q_HW 确立为晋升的权威。T 次运行表明，在这一共享合约下，模型在结构性修复方面的差异显著。每个模型仅进行一次实验，无法将模型效应与提供商或采样变化分离，且双仓库的任务套件限制了外部有效性。匹配的消融实验和重复实验必须建立 QoR-RAG 和失败反思的因果效应。更广泛的仓库、工具版本和设备将测试在当前 AMD 语料库之外的迁移能力。

## 附录 D：复现与结果刷新

接受的任务清单位于 `tasks/track_a_150/candidate_manifest.json`。三个源报告路径作为注释写在 `technical-paper/results_generated.tex` 的末尾。在替换或扩展 `runs/` 下的匹配目录后，从仓库根目录执行：

```
python3 technical-paper/scripts/update_results.py
```

该脚本选择最新的匹配最终报告，并拒绝生成宏，除非模型身份、任务数量、真实 API 状态、执行源代码哈希和信用额度限制一致。

生成的文件提供任务数量、结果文本值以及所有详细表格行。因此，刷新实验可以更新数值证据，而无需手动编辑论文。两个 PDF 图表是有意独立的矢量资产，必须在最终提交前从相同的报告集重新生成。仅评估器使用的测试和参考实现保持在智能体可见的文件系统之外；报告写入器会脱敏处理凭证和敏感路径。
