\section{Gate Evidence, Not Prompts}

LLM agents can edit unfamiliar HLS kernels, but only tool reports certify
correctness and hardware quality. A metered agent therefore needs a
promotion rule that preserves a verified fallback when any required
validation gate fails~\cite{amd2025vitis}.

Prior HLS agents automate code transformation, directive search, and
feedback-driven repair~\cite{xiong2024hlspilot,xu2024ralad,li2026chathls}.
Tool-using language agents alternate reasoning and actions~\cite{yao2023react}.
Our design assigns candidate promotion to deterministic HLS evidence under
explicit model and tool budgets.

The Verified-Candidate Loop (\VCL) contributes three findings.
\textbf{(1) Validation contract.} A fail-closed workflow preserves a
verified fallback across seven gates: Interface, \CSim, \Synth, Frequency,
Capacity, required \CoSim, and Metric completeness.
\textbf{(2) Hardware objective.} The bounded score $Q_{\mathrm{HW}}$ combines
effective latency, capacity-normalized resource footprint, and source-change
evidence to reject costly speedups.
\textbf{(3) Endpoint evaluation.} Qwen3.6-27B, the smallest model tested,
achieves the highest completion rate (\QwenThreeSixSuccessRate) and best
optimization quality (Section~\ref{sec:evaluation}). Architecture matters more
than parameter count for HLS repair.
