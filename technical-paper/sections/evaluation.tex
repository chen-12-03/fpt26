\section{Completion Outpaces Score Coverage}
\label{sec:evaluation}

\textbf{Protocol.} Three hosted endpoints process the same balanced
\CorpusTaskCount{}-task suite under one agent revision under the Track-A
contract~\cite{fpt26tracka}. The models span three architecture--scale
regimes: DeepSeek V4 Pro (1.6\,T MoE, 49\,B active), Qwen3.5-122B-A10B
(122\,B MoE, 10\,B active), and Qwen3.6-27B (27\,B dense).

\textbf{Results.} Table~\ref{tab:headline-results} and the repository's
per-category breakdown yield three patterns.

(1)~\textbf{Only explicit optimization improves quality.} All five
repair/generation categories cluster at the baseline
$Q_{\mathrm{HW}}{\approx}0.7576$ ($S{\approx}73.7$ with $E{=}0.973$).
The agent passes validation gates but performs no architecture-level
optimization on repair tasks.

(2)~\textbf{Architecture trumps parameter count.} Qwen3.6-27B achieves
\QwenThreeSixSuccessRate{} completion (\QwenThreeSixSuccessCount{}/
\CorpusTaskCount{}), including 25/25 on structural \CoSim{}, and leads
optimization quality (avg.\ $Q_{\mathrm{HW}}{=}0.812$, 60\% $>$76).
Qwen3.5-122B-A10B scores avg.\ $Q_{\mathrm{HW}}{=}0.775$ (28\% $>$76)
but trails on structural repair (80\% vs.\ 100\%). DeepSeek V4 Pro
(\DeepSeekSuccessCount{} completed, \DeepSeekTokensM{}M tokens,
3.1$\times$ Qwen3.6) averages only \DeepSeekQorScore{} on optimization
tasks---below the 73.2 baseline. Its candidates trade latency for area
(e.g., LUT +577\% to save 30\% latency), yielding $h{\approx}1$.

(3)~\textbf{The structural \CoSim{} category is the strongest model
discriminator.} The gap between the best (100\%) and worst (80\%)
structural repair rate exceeds the gap in any other category. CoSim
deadlock repair requires coordinated interface changes that appear to
favor dense architectures over MoE, consistent with the failure
classification in Section~\ref{sec:vcl}.

\takeaway{Qwen3.6-27B leads both completion and optimization quality;
architecture matters more than parameter count for HLS repair. Only
explicit optimization tasks benefit from LLM-driven QoR improvement.}
