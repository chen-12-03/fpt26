\section{Separated Evaluation Measures}
\label{sec:evaluation}

\textbf{Protocol.} Each configuration first processes the same frozen,
balanced \CorpusTaskCount{}-task Track-A v4 suite~\cite{fpt26tracka}. A
deterministic merge rule permits a retry only when the currently selected
record is classified as an LLM-API infrastructure error; the chronological
retry replaces it regardless of retry outcome. Validation failures and
900-second task timeouts are ineligible. First-pass public completions are
143, 129, and 131; after 0, 17, and 19 eligible retry records, the final counts
are 143, 140, and 141.

Public completion retains all 150 tasks. API-conditioned completion excludes
only unresolved LLM API-call records from its denominator and retains task
timeouts and validation failures. A separate evaluator reruns each
public-completed output using finite hidden \CSim, synthesis, and required
\CoSim{} gates. The QoR columns apply Eq.~\eqref{eq:score} to the same
\CommonQorTaskCount{} tasks.

\textbf{Results.} (1) All
\IndependentHiddenCorrectCount{}/\IndependentEvaluatedCount{} final outputs
that pass the public gate also pass the recorded finite hidden-gate suite. The
26 endpoint--task runs without public completion are outside this denominator;
the result is test-bounded evidence, not a correctness certificate.

(2) DeepSeek has the largest raw completion point estimate
(\DeepSeekSuccessRate); Qwen3.5 has the largest API-conditioned point estimate
(\QwenThreeFiveApiCleanRate). These answer different questions, so the latter
is not relabelled as agent completion.

(3) Qwen3.5 has the largest paired QoR point estimates. Its reference mean is
only 0.37 above Qwen3.6; one campaign per configuration provides no uncertainty
or stable-ranking claim. DeepSeek has the lowest observed selected-record
token total.

\textbf{Configuration boundary.} The recorded snapshots match in 83/86 files,
including controller, prompts, gates, and scoring; differences are confined to
provider/run-contract, metric-recording, and runner/record-validation plumbing.
Because the provider adapter is outside the snapshot, the rows compare complete
deployed configurations rather than isolating endpoint or model effects.
